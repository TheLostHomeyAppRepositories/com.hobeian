# Audit workflow

Apply the [authoring gate](../SKILL.md#authoring-gate) first. For a whole-driver or
subsystem campaign, also read [CAMPAIGN.md](../CAMPAIGN.md).

## Junk patterns

Investigate these candidates; retain them if they protect an independent contract:

- Assertion-free probes, self-comparisons, copied expectations, and expected
  values generated by the implementation under test.
- Copied manifests, export lists, and exact source/import greps that break on
  harmless refactors.
- Private predicate or internal call-shape tests duplicating stronger behavior
  coverage, or repeated replays of shared helpers.
- Test-only exports, globals, wrappers, or production paths with no real caller.
- Mocks implementing asserted behavior or pretending distinct APIs are identical.
- Fixtures fabricating acknowledgements, ordering, or persistence that production
  code should produce.
- Capability flags asserted instead of actual reported values or transitions.
- Negative controls failing at unrelated guards or never reaching the target.
- Test names promising behavior their inputs and assertions do not exercise.

## Retention bar

Keep the independent contracts listed in [SKILL.md](../SKILL.md#retention-bar),
including observable ordering and credible regressions. Static or slow does not
mean disposable. A failing baseline may expose a product bug; investigate rather
than deleting the test.

## Candidate evidence

Before editing, read the full test, production owner, entry points, callers,
callees, sibling coverage, dependency source/types where relevant, CI routing,
and history. Record each candidate's:

- Name/location and the detectable failure.
- Non-test callers of the covered production or support seam.
- Stronger remaining proof, or why no contract needs to remain.
- History, reason for existence, and any dead code its removal unlocks.
- Risk and focused validation command.

Missing evidence means no deletion. Keep discovery read-only until the evidence
and keeper coverage are recorded. Prefer a few high-confidence candidates.
Consolidate into the existing owner before removing overlapping coverage. Remove
obsolete seams; do not add replacement implementation tests to justify cleanup.

## Validation and handoff

Follow the [proof policy](proof-policy.md). Never edit a checkout during active
tests or builds. Run owner and sibling proof. If removing a source assertion,
exercise the real behavior it claimed to protect.

Check local links, targeted lint where applicable, `git diff --check`, and
`git diff --numstat`. Review deleted contracts against their keepers.
Report causes, removed categories/seams, retained contracts, proof and cost,
production versus test/support changes, PR state, and follow-ups. Refresh and
rediscover if the relevant source changes before another audit batch.
